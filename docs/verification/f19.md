# F19 operator/runtime evidence (2026-10-23 UTC)

The service dispatcher connects persisted Fetch, Metadata, Translate, Download,
Synthesize, Finalize and Archive phases. Each phase uses the claimed immutable
configuration, durable leases and bounded adapters. A separate command worker
can cancel an in-flight source job. Source capture, pinned view selection and
Fetch completion share one lease-fenced transaction. Finalize validates all
payloads before one fenced outbox/phase transaction; computation does not assert
recipient delivery. Native yt-dlp identity aliases survive semantic Git restore.

## Focused evidence

- Eight runtime fixtures cover stale/cancelled capture fencing, concurrent command
  cancellation, repeatable two-job/one-revision replay, independent pending
  deliveries, backup/restore hold, missing optional-tool diagnosis, offline doctor
  and synthetic-secret redaction, native-media alias Git roundtrip, and semantic
  filenames. The filename regression first failed at `archive.md`, then passed
  after the model title was sanitized and bounded to at most 183 UTF-8 bytes.
- The real CLI integration fixture exercised `replay`, `doctor`, `status`,
  `backup` and `restore-backup` in a private `/var/tmp` directory: two processing
  jobs complete, one canonical unchanged revision, two pending documents and a
  restored recovery hold. This is offline, not a Telegram delivery receipt.
- Telegram file-download contract checks passed against a synthetic HTTP server:
  valid lookup/download, descriptor traversal rejection, declared-size rejection,
  actual-stream byte bounds, cancellation and transport-error token redaction.
- Host Clippy with warnings denied passed after the filename/download changes.
- `systemd-analyze --user verify` passed for a copy of the supplied unit whose
  ExecStart points to the built debug executable. Verification of the published
  installed path remains part of the installation receipt.

A real user-systemd transient **synthetic parent/child** unit ran on systemd
252 (252.39-1~deb12u2), using the documented `KillMode=control-group` and
`Restart=on-failure` policy (shortened fixture restart/stop delays). The first
parent intentionally exited 23; systemd reported `NRestarts=1` and the first
TERM-resistant child disappeared. Stopping the restarted unit exited 0 and the
second TERM-resistant child disappeared. The test unit was stopped and collected.
No Telegram poller or application service was started. This proves manager
restart/cgroup behavior, not a completed production bot deployment.

## Diagnostic failures retained

An initial doctor probe failed because its temporary workspace did not explicitly
request mode 0700; it now uses the same private workspace rule as other tools.
An initial archive fixture incorrectly targeted the code worktree and was
rejected. A later backup fixture under `/tmp` encountered this host's pre-existing
`/tmp/.git` marker; a traced replay preserved the refusal. Fixtures now use the
existing recovery suite's `/var/tmp` isolation. Neither Git-boundary validation
nor private-directory checks were weakened. A prior untraced ENOENT was not
reproduced by the traced invocation and has no invented root-cause attribution.

The storage process-death fixture now captures its synthetic child stdout/stderr
on unexpected exit, preserving evidence of future panics instead of discarding
it. This does not retroactively explain the earlier F18 intermittent child exit.
