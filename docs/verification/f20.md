# F20 product and live acceptance

Project-Spec: `rust-telegram-archive-bot-v1`. Candidate: `0.1.0-rc.1`.
This report distinguishes deterministic checks, installed executable checks,
actual provider/API observations and client observations. It is not a claim of
production validation. See [capabilities.json](capabilities.json) for measured
durations, artifact hashes, executable identities and exact client versions.

## Product scenarios

- `product_shared_graph_translation_narration_export_restart_and_restore` runs
  the X graph, real Rust hymt bridge, ADK translation, supervised synthetic TTS,
  real FFmpeg validation, delivery preparation, Git projection and full restore.
  B quotes A and C replies to A: A is fetched once, three revisions remain,
  translation/TTS each run three times, both views pin A, and six independent
  delivery requests survive reopening. Replaying completed work calls neither
  provider again. Restore retains canonical equality and pauses all effects.
- `product_web_text_attachment_and_empty_text_pdf_keep_usable_originals` runs
  HTML extraction and text attachment narration through the dispatcher. Real
  FFmpeg produces/validates the synthetic audio. A valid blank PDF passes real
  Poppler validation, retains its exact bytes and document delivery, stays
  partial, and has neither a translation nor a narration claim.
- `product_cli_download_finalizes_only_valid_bytes_and_does_not_narrate_metadata`
  invokes the actual CLI and real namespace/relay with synthetic yt-dlp outputs.
  One playable download completes; damaged bytes fail with no ready artifact.
  Metadata-only source text is not narrated as a transcript.
- Existing ingress, ADK, delivery, projection and recovery crash fixtures remain
  part of the same complete test command. They test actual child death as well
  as transactional exceptions; the end-to-end scenarios do not replace them.

Focused receipts: all nine translation tests passed together in 111.68 seconds
using the release bridge; the CLI download scenario passed in 6.16 seconds;
the document/narration scenario and all-target Clippy passed. The document
fixture initially used the wrong internal row count and then a nonexistent
table name. Those two failed harness attempts are retained locally and are not
product failures or passing checks. Final complete gates are recorded in the
[release checklist](release-checklist.md).

Two status defects found during live acceptance were fixed with failing/passing
regressions: retries now count repeated attempts within a phase rather than
ordinary phase progression, and partial processing appears under `partial`
rather than `complete` in queue metrics. Source/job semantics are unchanged.

## Actual providers and Telegram

The installed application at `a844f7aa4312b16235bfb8e961725cfe6c75aa1b`
completed a synthetic English text job through the real configured model,
pinned hymt bridge and md2audio Edge TTS in 89.305 seconds. It produced one
completed job, a Markdown delivery and an Ogg/Opus narration. Five translation
segments completed with no retained-original/degraded segment. Remote effective
translation identity was not verified, so this result is not eligible for a
verified translation-cache claim. Transport completion does not establish
semantic fidelity or original-content completeness.

An explicitly authorized test chat received the Markdown and narration through
`examples/deliver_pending.rs` at `e86ba08`; both deliveries were confirmed.
The helper uses the production durable outbox and never starts a poller.
`examples/prepare_media.rs` at `0f8826f` then ran actual yt-dlp, the production
namespace/proxy, full finalizer and local Git export for two public recordings.
It is an opt-in adapter smoke, not a claim that the main dispatcher treats every
generic webpage URL as an audio-download request.

| --- | --- | --- | --- | --- |
| Synthetic English → Chinese narration | Ogg/Opus `voice_note`; 615,505 bytes | 104.280 s / 104 s | Confirmed `voice` | Blocked / blocked |
| Animals at Play recording | MP3 `audio_track`; 18,909,946 bytes | 1181.596 s / 1182 s | Confirmed `audio` | Blocked / blocked |

All three have full decode, a duration difference within 1000 ms and exact
published-byte SHA-256 evidence. The source listings are
[LibriVox Nonfiction 015](https://librivox.org/short-nonfiction-collection-vol-015/)
and [Sherlock Holmes version 2](https://librivox.org/the-adventures-of-sherlock-holmes-by-sir-arthur-conan-doyle/).
Only metadata/hashes are public here; audio and private test receipts stay out
of the source repository.

Two X URLs sampled read-only from operator drafts completed with **partial**
processing through the opt-in FxEmbed fallback: 12 complete source observations,
two error observations and 12 canonical revisions. No X bearer credential was
available, and enabling the official provider failed early as designed. Fallback
availability is not official-X acceptance or proof every referenced post was
retrieved. No draft was modified and no X-derived Telegram message was sent.

## Blocked and unperformed checks

- Desktop 4.6.5+ds-2+b1 on Debian 12: display `:0` exists, but read-only
  `xwininfo`/`xprop` failed X authorization. There is no accessible client session.
- Android Telegram 10.14.3 (49279), Android 14/API 34, Pixel 4a (5G): ADB is
  authorized, but the device is locked/asleep at NotificationShade. No seek or
  speed interaction was performed. The operator was asked to unlock/open the
  test conversation; no unlock is assumed.
- Official X API is blocked by its missing bearer credential. A configured
  model, Edge TTS and Telegram test chat were available and actually exercised.
- Local TTS and multi-speaker live synthesis, production polling, replacement of
  the legacy bot, live remote Git push, physical power-loss recovery and audible
  human quality evaluation were not performed. Relevant deterministic contracts
  remain tested. No claim is made about a prior user-failing audio file.

Client residuals are tracked in [#41](https://github.com/RyderFreeman4Logos/telegram-archive-bot/issues/41).
The specification permits a prerelease with pending live validation; it does not
permit calling that release production-validated.

## Repeat the opt-in checks

Use a fresh private state/archive and authorized chat, with polling and push
disabled. Set actual tool entry points and secret references in the config.
Keep model/media request budgets realistic for the input. Commands below access
configured services and the second command sends pending Telegram messages:

```sh
telegram-archive-bot --config /private/test.toml replay /private/synthetic-updates.json
cargo run --locked --example deliver_pending -- --config /private/test.toml --send --limit 10
cargo run --locked --example prepare_media -- --config /private/fresh-media.toml \
  --url https://archive.org/download/nonfiction015_librivox/animalsatplay_dixon_bt.mp3 \
  --relay "$HOME/.local/bin/telegram-archive-bot" --run
```

Inspect any nonconfirmed delivery without blindly resending. Use the documented
explicit resend acknowledgement for `unknown`; repeating a helper is not an
acceptance criterion. Client playback observations must be added separately.
