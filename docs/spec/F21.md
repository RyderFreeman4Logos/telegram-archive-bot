## Outcome
Users can find archived content while authoritative storage remains independent of indexes.
## Implementation scope
This is optional after the core release. Start with SQLite FTS for keyword retrieval, then add a feature-gated LanceDB adapter if semantic retrieval is useful. Index chunks referencing exact source revisions with offsets and a versioned chunk policy.
Record embedding model/deployment identity, dimensions, normalization, and configuration. Build embeddings through the typed workflow/provider boundary. Maintain incremental indexing via outbox checkpoints; deletions or superseded records follow a documented visibility policy while historical views stay intact.
Rebuild indexes from canonical records. Never use embedding similarity to merge source identities, and never make the index the only copy of text or job state.
## Acceptance criteria
- Keyword search works with no vector database installed.
- Deleting and rebuilding the optional index produces equivalent source/revision coverage.
- Model, dimension, or chunk-policy changes cannot mix incompatible vectors.
- Results identify their source, revision, and matching text span and honor authorization.
- Index outages do not block ingestion or canonical archive access.
- Performance claims use a documented synthetic/public corpus and measured workload.
