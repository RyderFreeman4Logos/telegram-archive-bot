## Outcome
Long-running work resumes after restart and exposes a truthful phase-by-phase state.
## Implementation scope
Implement queued/running/retry/succeeded/partial/failed/cancelled jobs, attempts, retry scheduling, immutable config/input references, artifact outputs, leases/heartbeats, and fencing. Processing state, delivery state, and projection state remain separate.
Use short atomic claims and bounded per-resource concurrency. Persist a finite attempt/deadline budget across restarts. Explicitly classify retryable errors, terminal errors, partial extraction, cancellation, and uncertain side effects. Integrate ADK resume through a durable run mapping rather than inventing another graph engine.
Expose host operations for status, retry of a chosen failed phase, cancellation, and retained-artifact retrieval; Telegram command wiring belongs to F15. Resume successful stages from recorded outputs. Apply shutdown drain/cancel deadlines.
## Acceptance criteria
- Killing a worker after producing an artifact does not rerun a successful expensive stage on recovery.
- Expired/stale leases cannot overwrite the selected result of a newer owner.
- Restarts do not reset attempt limits or extend the absolute deadline indefinitely.
- Cancellation is durable and propagates to model streams and supervised subprocess groups.
- A failed delivery or Git push does not mark source archival as lost.
- Focused tests cover claims, lease expiry, crash recovery, retry budget, partial state, and graceful shutdown.
## Shared definition of done
Implemented behavior satisfies the criteria above, focused checks record actual evidence, relevant public documentation is updated, and no production secrets or user archive data enter the public code repository. Resolve dependency Spec-IDs to issue links while retaining the stable IDs.
