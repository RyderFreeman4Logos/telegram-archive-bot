## Outcome
Canonical records and large files remain consistent across concurrency, crashes, and cleanup.
## Implementation scope
Create versioned SQLite migrations and repository APIs for sources, revisions, observations, relations, views, artifacts, inbox/jobs, outbox, and projection cursors. Use foreign keys on every connection, unique constraints, appropriate NOT NULL/STRICT typing, WAL on local disk, and short transactions.
Implement a managed content-addressed blob store with same-filesystem staging, hashing, validation, durable publication, and reference cataloguing. Track publication leases or equivalent fencing so garbage collection cannot race an active publisher. Do not mark an artifact ready before its profile-specific validation succeeds.
Publish bytes before committing a ready database reference. Orphans and interrupted partial files are recoverable. Distinguish a blob's byte identity from a derivative's semantic identity and a delivery's identity.
## Acceptance criteria
- Concurrent inserts preserve identity uniqueness; invalid foreign keys fail.
- A crash before/after file publication and before/after catalog commit leaves no accepted ready reference to absent bytes.
- Identical blob digests converge on immutable identical bytes; unexpected collisions or corruption fail explicitly.
- Missing/corrupt blobs are detected on verification and never accepted as cache hits.
- GC respects active publications, retained references, and backup pins.
- Network, LLM, subprocess, and Git work never holds a write transaction.
- Migration and integrity checks run against a fresh database and a prior supported schema.
## Shared definition of done
Implemented behavior satisfies the criteria above, focused checks record actual evidence, relevant public documentation is updated, and no production secrets or user archive data enter the public code repository. Resolve dependency Spec-IDs to issue links while retaining the stable IDs.
