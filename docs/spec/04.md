# 04 — ADK, hymt & Media Integrations

## Scope and verified baseline
This specification targets a **new public Rust Telegram archive/audio bot**. It does not authorize modifications to the existing `drafts` bot. All examples must use placeholders; host addresses, credentials, private archive content, and existing deployment settings must not enter the public repository.

## Shared execution contract
Every adapter consumes immutable source/artifact references and a validated configuration snapshot. It returns typed metadata plus staged output references. Only the host artifact service publishes validated outputs. Agent-generated text cannot choose executable names, arbitrary filesystem paths, SQL, destination chats, or Git commands.
Record source revision, ordered input hashes, adapter/tool version, prompt/schema version, model/profile identity, effective configuration fingerprint, timestamps, and status. Preserve original source text; translations and summaries are distinct derivatives. Cache reuse requires the same complete derivation identity. An incomplete or degraded result must not masquerade as a successful equivalent.
The **durable job runner owns retry policy and the absolute deadline**. Proposed defaults are a 1,700-second LLM attempt timeout, three total attempts for a retryable stage, and a configurable six-hour job deadline. These are product defaults, not upstream defaults. Queue waiting does not consume the execution deadline; execution and retry backoff do. Disallow starting an attempt that cannot fit the remaining budget. Disable independent ADK/provider and hymt network retries in this integration unless a later change explicitly delegates a bounded portion of the same persisted budget. Protocol-correction attempts must also be bounded and recorded.
Cancellation must stop response-stream consumption and reap supervised process groups. A timeout around obtaining a stream is insufficient: the deadline covers its entire consumption. After an ambiguous external send, do not claim exactly-once delivery. Telegram delivery and Git export remain host-controlled outbox operations outside LLM authority.
Hot reload affects new jobs. Running jobs retain their configuration snapshots; changing the model, profile, prompt, voice, or rendering rules creates a new derivation identity.

## ADK workflow requirements (F10)
### Problem and outcome
The bot needs model-backed summaries, semantic titles, classifications, and optional narration scripts with reproducible inputs and validated outputs. These operations must resume after interruption without confusing a completed graph step with completed Telegram delivery.
### Implementation
Build a small, deterministic Rust workflow whose LLM stages use ADK-Rust. Use explicit provider configuration, including an OpenAI-compatible endpoint for a local model. Compile only required capabilities. Do not expose generic shell, unrestricted HTTP, Git, or filesystem tools to an agent.
Define versioned Rust/Serde result types. A metadata result should contain a display title, summary, language, tags, and source-block references supporting its claims. A narration result must identify its source revisions and transformation mode. Budget input with the configured tokenizer or documented conservative fallback, reserve output tokens, and split even a single oversized paragraph. Preserve source block references through chunking. Apply schema and domain validation before publication. Unknown source references, malformed results, refusals, exhausted token budgets, and interrupted streams must produce explicit outcomes rather than empty successful artifacts. Bound correction attempts. Validate source references independently; syntactic JSON validity does not establish factual fidelity.
Use `SqliteCheckpointer` where the workflow must survive process restarts. Persist the mapping between domain job ID, graph thread ID, configuration fingerprint, and input revisions. A recovery worker must discover interrupted jobs and invoke resume; persistence alone is not a scheduler. Keep large source bodies and binary artifacts outside checkpoints, using immutable references.
ADK graph nodes execute **at least once**. A crash before the super-step checkpoint can rerun work that already finished. Commit derivatives idempotently using their derivation key and keep external delivery/export in their own outboxes. Do not attempt to wrap Telegram, Git, and SQLite in a fictional shared transaction.
Handle the inspected v2.3.0 streaming contract: the terminal event may contain the complete response with `provider_metadata.content_complete = true`. Use `adk_core::EventTextDeltas` or replace content for the corresponding event ID. Never append the complete terminal response a second time.
### Acceptance criteria
- A fixture model produces a validated derivative linked to exact source revisions; malformed output cannot become a successful artifact.
- Restarting after a committed checkpoint resumes the expected frontier. Restarting before checkpoint persistence may rerun a node but cannot duplicate the published derivative.
- A stream of partial events followed by a complete terminal event produces exactly one final text.
- Cancellation and the configured deadline cover a silent/slow model and the entire response stream.
- Attempts remain within the persisted job budget after restart; authentication/configuration failures are not repeatedly retried.
- Model inputs, outputs, versions, and outcomes are auditable with secrets redacted.
### Dependencies
Depends on **F02 (configuration), F03 (SQLite/CAS), F04 (source identities/revisions), and F06 (durable jobs)**. Use fake adapters until F11/F12 land. The later F15/F16 delivery/export integrations consume host-owned artifacts; they are not prerequisites for F10.

## Translation requirements (F11)
### Problem and outcome
Translation should reuse hymt's existing segmentation, tokenizer budgeting, Markdown handling, and verified caching. It must not introduce a second independent translation pipeline or nested unbounded retries.
### Implementation
Implement a host-owned `Translator` interface taking source revision, target language, translation profile, and execution context. The primary implementation uses `hymt-translate`, whose inspected exports include `plan_translation`, `translate_text`, `translate_file`, streaming functions, `TranslationCtx`, and `TranslationOutcome`. Initialize the corresponding core/client/segment/cache dependencies explicitly. Pin a Git revision while package versions remain insufficient to identify the audited implementation. The inspected TranslationCtx holds a concrete TranslationClient, not an interchangeable ADK model trait. ADK invokes the host translator adapter; hymt retains its internal client. Requiring all provider calls through an ADK model would require a separately designed trait/refactor.
Construct a per-job configuration with `HotConfig::from_path` and retain a detached snapshot using `HotConfig::detached_snapshot()`. Do not mutate an operator's interactive hymt configuration. Keep provider sampler defaults unless an explicit job override is supplied. Disable hymt's independent network retries for this adapter: the inspected default is **100 additional retries**, with a 600-second per-attempt timeout. Combining that with a 1,700-second timeout and outer retries is unacceptable.
Map hymt progress into typed stage events; do not use token arrival as proof of completion. Publish only after the final outcome. Enable compatible application caching deliberately: it is disabled upstream by default. Preserve hymt's verification requirements; do not reuse unverified cache entries merely because text hashes match.
Record preserved source regions and degraded/protocol-truncated outcomes. Current hymt deliberately does not treat every semantic omission, changed URL, or empty completed model string as a transport error. The adapter must report that distinction, retain original source, and avoid claiming semantic completeness. Optional review belongs to a separately versioned ADK stage. Do not translate the whole document again merely to generate a title or summary.
### Acceptance criteria
- Mixed-language Markdown, protected code, Unicode, and a multi-segment document preserve source identity and produce a separate translation artifact.
- A cancellation or failed segment never publishes a partial document as complete.
- Unchanged verified inputs can reuse eligible cache entries; changed profile/prompt/configuration cannot reuse an incompatible derivative.
- Job retry/deadline limits hold even when the underlying upstream defaults differ.
- A mid-job hot reload cannot change that job's selected profile or effective configuration.
- Tests distinguish transport completion, protocol truncation, and semantic quality; they do not invent a guarantee that hymt supplies.
### Dependencies
Depends on **F10's typed workflow contract and F02 (configuration)**, with storage/jobs inherited through F10. Its implementation can proceed alongside F10 after the interfaces are agreed.

## Media-download requirements (F12)
### Problem and outcome
The bot must download supported media without depending on human-readable console logs, guessed output filenames, or a download-complete signal that precedes failing post-processing.
### Implementation
Invoke the installed executable with an argument array, a private job directory, and a controlled environment. Use `--ignore-config`; default to `--no-playlist` unless the request explicitly permits a bounded playlist. Set output templates, resource limits, socket timeout, and retry settings from validated policy. Do not accept arbitrary user-supplied CLI switches.
Use official structured facilities: `-J`/`--dump-single-json` for metadata and `--print`, `--print-to-file`, or `--progress-template` for controlled output. Metadata-only `-J` normally simulates; a combined metadata-and-download invocation must explicitly account for `--no-simulate`. Capture the final path at **`after_move`**, after post-processing, rather than assuming the pre-processing extension remains correct. Prefer JSON-escaped template values or a dedicated result file when filenames may contain special characters.
Validate reported paths remain within the job directory. Distinguish metadata extraction, download, post-processing, and finalization. Return an audio candidate requiring the F14 finalizer before ready-artifact publication or Telegram delivery; F12 does not itself claim finalization. Source-provided duration is advisory. Retain selected metadata and extractor/source identity, while excluding cookies, signed URLs, headers, and credentials from public exports and logs.
### Acceptance criteria
- Fixture CLI runs demonstrate metadata-only behavior, actual download, changed post-processing extension, and failed post-processing.
- Ordinary human log changes do not break the parser.
- A reported download success followed by post-processing failure cannot publish a ready artifact.
- Cancellation/timeout terminates and reaps yt-dlp and descendant FFmpeg processes.
- Default handling does not accidentally download a playlist; explicitly permitted playlists obey limits.
- Candidate paths, sizes, content hashes, tool versions, and a pending-finalization status are recorded; F14/F20 verify the integrated finalization path.
### Dependencies
Depends on **F02 (configuration), F03 (SQLite/CAS), and F07 (process supervisor)**. F14 later consumes its audio candidates. F12 does not depend on F10, F11, or F14 implementation.
