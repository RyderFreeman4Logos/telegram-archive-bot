## Outcome
An operator can optionally bring historical files into the new canonical model with explicit provenance and uncertainty.
## Implementation scope
This is optional and has no prerequisite role in the greenfield MVP. Read an explicitly configured local legacy archive root in read-only mode. Begin with dry-run inventory and a mapping report. Preserve original file bytes/hashes, relative paths, and importer version.
Extract reliable platform IDs and relations when evidence exists. Preserve uncertain expanded documents as legacy document records rather than inventing tweet IDs or stripping repeated text heuristically. Record mapping confidence and collisions for review.
Make import resumable and idempotent. Keep old source files unchanged. Never import credentials, executable code, runtime secrets, or a whole old repository history into the public application repository. Imported data belongs to the configured archive/state destination.
## Acceptance criteria
- A dry run makes no archive/state mutations and reports what would be imported.
- Repeating a completed import creates no duplicate canonical records or derived artifacts.
- Known A/B/C IDs converge to correct identities and relations; uncertain documents retain lossless originals.
- Collision and partial-parse reports preserve evidence without silent overwrites.
- Source files have identical hashes before and after import.
- Import interruption resumes from durable checkpoints.
- Existing-new-format semantic restore remains F17; legacy format handling is clearly separate.
## Shared definition of done
Implemented behavior satisfies the criteria above, focused checks record actual evidence, relevant public documentation is updated, and no production secrets or user archive data enter the public code repository. Resolve dependency Spec-IDs to issue links while retaining the stable IDs.
