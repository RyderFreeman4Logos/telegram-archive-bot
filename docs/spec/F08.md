## Outcome
X content becomes a graph of canonical sources rather than repeated expanded Markdown blobs.
## Implementation scope
Implement a pluggable X provider adapter and documented fallback capabilities. Resolve status IDs across X/Twitter URL aliases, traverse reply ancestors and nested quote/repost relationships, and hydrate supported X Articles. Return typed source objects, observations, provenance, completeness, and relations.
Use a request-wide visited set and shared fetch cache plus cross-job identity coordination. Recommended default reply-ancestor limit is 25; expose bounded total nodes, nested depth, bytes, and time. Limits and missing nodes appear in the view manifest.
Fetch failures retain useful partial results. Provider authentication and outages are distinct from deleted content. Generate readable pinned views without permanently duplicating quoted bodies. Do not use obsolete renderer-specific helpers from the old project.
## Acceptance criteria
- Synthetic A/B/C fixtures fetch unchanged shared A at most once per traversal and store one canonical A revision.
- Alias URLs, changed handles, missing parents, cycles, deleted nodes, excerpts, and article hydration are covered.
- A partial quoted excerpt cannot overwrite a full source.
- Provider fallback records which provider supplied each observation and its limitations.
- Bounded traversal stops deterministically and reports what was omitted.
- No supported provider configuration is required to run CI fixtures; live capabilities are honestly documented.
## Shared definition of done
Implemented behavior satisfies the criteria above, focused checks record actual evidence, relevant public documentation is updated, and no production secrets or user archive data enter the public code repository. Resolve dependency Spec-IDs to issue links while retaining the stable IDs.
