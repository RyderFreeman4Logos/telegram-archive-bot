## Outcome
Operators can configure providers, resources, authorization, storage, and delivery without modifying source code.
## Implementation scope
Implement typed TOML configuration, XDG defaults, explicit path overrides, and secrets supplied through environment variables or restricted files. Validate all options and reject unsafe or unsupported combinations. Add an explicit chat/user authorization policy.
Create immutable, non-secret configuration snapshots for jobs. Store model deployment revision, requested language, prompts, translation profile, voice policy, media limits, and selected tool versions. Do not hash raw secrets into cache identities.
Use separate attempt timeout, maximum-attempt, and whole-job deadline fields. A 1700-second local-LLM attempt timeout is a proposed configurable default; define other phase budgets separately and document the effective total. Implement atomic SIGHUP/reload behavior for supported settings and clear restart requirements for the rest.
## Acceptance criteria
- Missing credentials, invalid TOML, and unknown settings fail with actionable redacted errors.
- A failed reload keeps the previous valid configuration.
- New jobs use the new snapshot while in-flight jobs retain the previous one.
- Logs, stored snapshots, manifests, and error URLs contain no secret values.
- Unsupported local-TTS/multi-speaker or delivery-format combinations are rejected before work begins.
- Unit tests cover precedence, snapshot stability, authorization, and invalid reload behavior.
## Shared definition of done
Implemented behavior satisfies the criteria above, focused checks record actual evidence, relevant public documentation is updated, and no production secrets or user archive data enter the public code repository. Resolve dependency Spec-IDs to issue links while retaining the stable IDs.
