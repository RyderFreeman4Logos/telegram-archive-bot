## Problem
Upload success, playable media, and a visible speed control are different outcomes. Network ambiguity and crashes also make untracked immediate sends unreliable and can cause duplicate messages or wasted synthesis.
## Scope
Implement bot-scoped media reuse, explicit presentation profiles, validated request metadata, persisted delivery attempts/receipts, rate-limit handling, ambiguous-send recovery, and retention-aware cleanup. Keep publication side effects outside LLM tools and producer adapters. Add durable document/text delivery for source PDFs and derived Markdown, correct caption escaping and length handling, and authorized /status, /cancel, /retry, /get, /refresh, and /resend command wiring to host operations. Non-audio deliveries have the same attempt/ambiguity discipline without an audio-finalizer requirement.
## Dependencies
F03 (SQLite/CAS storage), F05 (Telegram ingress and bot integration), F06 (durable jobs), and F14 (audio finalization). Integrate F12/F13 end-to-end behavior at F20; do not add a producer dependency that prevents testing delivery against validated fixtures.
## Acceptance criteria
- Requests include validated duration and correct MIME; responses persist expected media type, message identifier, duration, and reusable file identifiers.
- A response with missing or inconsistent media metadata remains diagnosable and does not silently pass product validation.
- Cached `file_id` reuse never crosses bot identities or incompatible presentation types; rejection falls back to upload.
- Timeouts after transmission and crashes during sending recover as `delivery_unknown`, without automatic claims of success or exactly-once delivery.
- Pending, failed-retryable, and unknown deliveries retain their artifacts; retries never rerun upstream synthesis or translation.
- A controlled integration test verifies real duration, seeking, and intended speed behavior for short voice notes and audio tracks around the Desktop threshold. Record client versions; CI mocks alone cannot certify UI behavior.
- Unit/integration tests cover explicit rate limits, transient failures, malformed responses, ambiguous timeouts, and restart recovery without using production credentials.
## Evidence
[Telegram Bot API](https://core.telegram.org/bots/api) and [audited Desktop playback behavior](https://github.com/telegramdesktop/tdesktop/blob/v7.3.3/Telegram/SourceFiles/data/data_audio_msg_id.cpp).
