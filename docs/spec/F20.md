## Outcome
The first release demonstrates the actual product invariants across all adapters, persistence, audio, delivery, and recovery.
## Implementation scope
Run the Verification & Release Gates specification G01–G12. Create synthetic end-to-end scenarios covering shared X sources, webpage extraction, a usable PDF with failed text extraction, text attachment narration, translation, yt-dlp download, audio finalization, delivery failures, Git export, worker restart, and backup/restore.
Use real FFmpeg/ffprobe for media fixtures and deterministic fake external providers in CI. Provide opt-in live checks for configured X/translation/TTS/Telegram services. Record exact dependency and client versions.
For audio, validate short narration plus ordinary tracks below and above the inspected Desktop boundary. Record actual returned Telegram type/duration, seek behavior, and speed UI on the operator's chosen Desktop/Android clients. An unavailable credential or client is a pending live gate, not an invented success.
## Acceptance criteria
- All core feature acceptance criteria and G01–G12 have explicit evidence.
- A/B/C source sharing preserves one canonical unchanged A revision and correct pinned views.
- Bad or incomplete media cannot become a verified successful delivery artifact.
- Accepted input, completed computation, ambiguous send, committed export, and backup recovery crash scenarios have correct states.
- A new clone/install works without old repository files or private history.
- A release checklist identifies performed, skipped, and externally blocked checks accurately.
- Release notes include supported capabilities, tested versions, operational limits, upgrade/restore instructions, and known gaps.
- Publish a release candidate with truthful validation status; call it production-validated only after required live gates pass.
## Shared definition of done
Implemented behavior satisfies the criteria above, focused checks record actual evidence, relevant public documentation is updated, and no production secrets or user archive data enter the public code repository. Resolve dependency Spec-IDs to issue links while retaining the stable IDs.
