## Outcome
Every acknowledged authorized request has durable work or an explicit recorded rejection.
## Implementation scope
Implement long polling with a bot-scoped persistent update identity and next offset. In one transaction save the inbox record, normalized request, all child jobs, and cursor. Advance polling confirmation only after that transaction commits.
Parse URLs from text, captions, and Telegram entities; handle bounded Markdown/text document submissions. Multiple URLs create ordered child jobs under one request. Validate authorization and basic size/type limits before scheduling external work.
Polling must remain responsive while workers download, translate, synthesize, or upload. Replayed updates are idempotent. Route commands and future callbacks through the same authorization policy; do not leak another chat's jobs or artifacts.
## Acceptance criteria
- Replaying a Telegram update creates no duplicate jobs.
- Fault injection before/after the input transaction and before polling confirmation loses no acknowledged work.
- Multiple URLs and document inputs produce stable, independent child jobs.
- Unauthorized or invalid requests invoke no source, model, or media provider.
- A slow worker does not block polling or status handling.
- The persisted cursor is bot-scoped and resumable; update payload retention follows a documented policy.
## Shared definition of done
Implemented behavior satisfies the criteria above, focused checks record actual evidence, relevant public documentation is updated, and no production secrets or user archive data enter the public code repository. Resolve dependency Spec-IDs to issue links while retaining the stable IDs.
