## Implementation workflow
Follow the dependency manifest and work in reviewable branches. Independent adapters may be developed concurrently after their interfaces exist. Preserve a working vertical slice throughout development.
Each feature requires implemented behavior, focused verification, updated user/operator documentation where relevant, and an issue comment or PR description containing the actual evidence. Link PRs to their feature issues. Do not close an issue simply because an interface or mock exists.
Record departures from recommended defaults as an ADR explaining the observed reason, effect on invariants, and migration implications. Normal library choices and minor naming choices do not require a new user approval. Never silently drop a core acceptance criterion.
Stop only at a concrete external blocker: unavailable repository permission, missing integration credentials for a live test, or an unresolved product choice that would materially change behavior. Continue all independent work. For unavailable live credentials, complete deterministic tests and mark the exact live release gate pending; never invent a successful Telegram or model-provider test.
