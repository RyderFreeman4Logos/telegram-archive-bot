# 06 — Configuration, Operations & Recovery

## Configuration model
Use a typed TOML configuration with an XDG-compatible default location and an explicit CLI path override. Support environment variables or permission-restricted files for secrets. The example configuration contains placeholders only.
Separate source providers, model endpoints, translation policy, synthesis profiles, audio delivery profiles, storage paths, Git target, resource limits, and authorization rules. Validate the complete configuration before activating it.
Recommended defaults are a single-host local-disk deployment, an explicit allowlist of chats/users, no playlist expansion, bounded source-graph traversal, and narration in voice-message mode. Unknown configuration keys and invalid combinations should produce actionable errors.
## Timeouts and retries
Use phase-specific attempt timeouts, finite maximum attempts, exponential backoff with jitter where appropriate, and a whole-job deadline. Choose one owner for retries at each boundary. Respect Telegram rate-limit information.
For a slow local LLM, 1700 seconds is a configurable proposed per-attempt default, not a universal timeout for downloads, Edge TTS, local TTS, or FFmpeg. Document effective worst-case budgets. Bound lower-level hymt retries when the outer job supervisor owns them.
Rate limits, provider credentials, unreachable sources, malformed media, and cancellation have different handling. Retry only failures that can plausibly succeed without a changed input; keep terminal diagnostics and partial artifacts.
## Hot reload
Support SIGHUP or an equivalent documented reload command for non-secret configuration where feasible. Validate a replacement configuration atomically. New jobs use the new immutable configuration snapshot; running jobs continue with their previous snapshot unless explicitly restarted.
Do not serialize API keys into snapshots. Store secret references and a non-secret configuration version. If an upstream client cannot change an endpoint/profile in place, construct a new client for new jobs or require a documented service restart. Never claim a setting has been reloaded when its active client still uses the old value.
## Diagnostics and observability
Provide an offline-capable doctor command that checks required executables, versions, codecs, local paths, file permissions, database migrations, configured capabilities, and readiness without sending a Telegram message. Network/provider probes are explicit.
Emit structured, redacted logs with job ID, phase, attempt, source ID, artifact hash, and delivery ID. Do not log bot-token URLs, authorization headers, cookies, signed download URLs, entire private source documents, or model prompts by default.
Expose queue depth, processing duration, retries, token/cost estimates where available, cache hit rate, artifact retention, Git projection lag, and disk usage through logs or a simple local metrics endpoint. Avoid adding a monitoring service as an MVP dependency.
## Deployment
Provide a documented Linux user-systemd installation with explicit environment/config paths, restart behavior, graceful termination, writable-state directories, and a pinned tool installation strategy. Keep development, state, and exported archive locations separate.
The executable should fail early when required configuration is missing. Optional features should report disabled capability rather than crash the entire service. Document how to install and verify yt-dlp, md2audio, FFmpeg/ffprobe, and any PDF/web extraction helper.
Do not update external binaries on every job. Record tested versions; update through a deliberate release/deployment step with a focused compatibility test.
A container example is optional. Do not make containers, a queue broker, or a cloud database a requirement for the initial deployment.
## Recovery and maintenance
Back up SQLite consistently with its supported backup mechanism and include every referenced immutable blob. A raw copy of only the main file of a live WAL database is not a complete backup. The restore procedure verifies referenced hashes before resuming workers.
Artifact retention is state-aware: failed or uncertain delivery keeps the relevant artifact until an explicit retention policy permits cleanup. Garbage collection uses a recorded reference set, a grace period, and protection against in-flight publishers and backups.
A Git text export can restore semantic source data and textual derivations but cannot restore omitted binary audio or all operational history. Full backup and Git-only rebuild are separate operator commands and separate tests.
A user may edit an export only through a deliberate import workflow that creates a new source/derived revision with an expected prior revision. Do not treat Git and SQLite as uncontrolled concurrent writers.
## Production activation
Fresh deployment can use a separate test bot. If the operator later replaces an existing bot, compare output through offline replay first, stop the old poller, take a backup, then start one new poller with a recorded cursor and rollback procedure.
Implementation and live activation are different completion states. Never silently poll a real bot, send test messages to arbitrary chats, or push a personal archive while only documenting installation. The operator supplies the configured destination and credentials for an authorized smoke test.
