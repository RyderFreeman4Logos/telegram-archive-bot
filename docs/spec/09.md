# 09 — Feature Backlog (22 Issue Definitions)

## Backlog contract
This page contains **22 real child pages**, each an issue definition for the new repository. F01–F20 are core release requirements. F21 and F22 are optional Post-MVP enhancements.
These are specification pages, not claims that GitHub issues or code already exist. The implementation agent should use the Agent Handoff to create the issues in the new public repository and maintain the Spec-ID mapping.
Copy only each page's Issue-ready body into its public GitHub issue, plus the suggested title and labels. Resolve Spec-ID dependencies to the new issue URLs. Page navigation and private handoff links are not part of the public body.

## Suggested execution waves
1. Create F01 and the complete issue map. Establish F02 configuration and interfaces.
2. Implement F03 storage and F07 process supervision; then F04 identities, F05 ingress, and F06 jobs.
3. Build F08/F09 source adapters, F10 ADK, F12 yt-dlp, F13 md2audio, F14 finalization, F16 Git projection, and F18 cache in parallel where interfaces permit.
4. Integrate F11 hymt, F15 delivery, and F17 recovery as their prerequisites become available.
5. Complete F19 operations and F20 release gates. Keep the text-document-to-audio vertical slice working throughout.
6. Implement F21 search or F22 legacy import only as optional follow-up; neither blocks core acceptance.
The dependency manifest is authoritative over a casual reading of this suggested order. Integration tests in F20 join independent producer/finalizer/delivery work; do not create artificial circular dependencies between them.
## Issue completion discipline
Every issue contains a product outcome, implementation scope, dependencies, and observable acceptance criteria. Mark it complete only after the behavior and evidence exist. A mock proves an interface; it does not certify an actual provider, playable Telegram media, or client UI.
Reference the relevant architecture/specification page during implementation. Apply the shared contracts for secrets, provenance, cancellation, and public code/data separation to every feature.
