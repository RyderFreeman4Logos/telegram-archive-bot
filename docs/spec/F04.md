## Outcome
Shared sources are stored once per meaningful revision while every submitted discussion remains reconstructable.
## Implementation scope
Define provider-native identity, conservative URL aliases, immutable source revisions, fetch observations, typed relation edges, missing-source stubs, and ordered revision-pinned view manifests.
X status identity is independent of domain aliases and author handles. General web normalization preserves semantic queries and hash routes unless a provider policy proves an alias. Do not merge by embedding similarity or generated title.
Content hashes exclude fetch timestamps and volatile counters. Keep extraction provenance in observations. Complete content must not be downgraded by a quoted preview, fetch failure, or deletion. New real content creates a new revision. Rendering related context is separate from storing canonical content.
## Acceptance criteria
- A, B quoting A, and C replying to A produce three sources, three unchanged revisions, and correct edges in any submission order.
- Concurrent duplicate submissions preserve uniqueness; known X aliases resolve to the same identity.
- Distinct generic queries such as different values of a semantic query parameter remain distinct.
- Updating A leaves earlier views pinned to A's earlier revision.
- Counters-only changes create observations without duplicate body revisions.
- Partial previews, missing targets, cycles, and eventual stub hydration have explicit behavior.
- A view records missing nodes, ordering, expansion policy, and the actual archived revisions; it makes no unsupported claim about what a historical author originally saw.
## Shared definition of done
Implemented behavior satisfies the criteria above, focused checks record actual evidence, relevant public documentation is updated, and no production secrets or user archive data enter the public code repository. Resolve dependency Spec-IDs to issue links while retaining the stable IDs.
